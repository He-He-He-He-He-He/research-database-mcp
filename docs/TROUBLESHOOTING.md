# 常见问题与排查

[返回首页](../README.md) · [安装教程](QUICKSTART.md) · [配置指南](CONFIGURATION.md)

## 这到底是资料库、搜索引擎，还是接口？

它是让 AI 发现和调用不同研究来源的工具。包里主要是适配代码、命令索引和引导，不是预先搜集好的研究结果。问题由你提出，AI 再选择命令查询。工具不会替代 AI 的研究判断，也不承诺覆盖互联网或每个数据库的全部资料。

## 我不是程序员，可以用吗？

可以把整个解压文件夹交给有工具执行能力的 AI，并使用首页的安装提示。AI 需要能启动本机 stdio MCP；只有文件上传或文字对话能力的平台不会因此自动获得运行权限。

## 三种模式怎样选，会收费吗？

一般 general 开放全部无需个人凭据/机构网络的命令；浙大内网 zju 再开放机构 IP 命令；登录 login 再按需配置个人账号/API 凭据。模式本身不是收费等级。第三方是否收费、审批、限额以其实际产品为准。旧 partial/full 兼容为 general/login。

## 为什么有些公开功能仍不能用？

一般模式不再限制到 42 条起步样例，但仍需网络、正确参数、依赖与实际公开文件。某来源改版、限流或停用时，放开命令不会自动修复上游。目录里的代码存在不等于已逐项验收。

## 在校园网里，是否能直接访问校内库？

选 zju，使用 MCP **实际运行机器**的校园出口核验 IP/机构访问。无需个人登录的资源不必为了本工具额外注册，但仍须学校订购且相应适配器正常。login 中需要机构 IP 的命令同样不例外。云端容器不会自动继承电脑校园网，换学校也可能需要调整特定学校断言。

## 没有代理，外网会被跳过吗？

不以有没有代理判断。普通网络能连通的国外来源照常查询；真实出现明确连接失败时，自动短暂跳过同一命令 60 秒，继续其他来源。不同命令不因一个来源失败而被全局禁用。可用 research_setup 的 network_status 查看、network_reset 清除等待。401/403/429、文件或依赖问题单独处理，不伪装成断网。

## 为什么浏览器能打开，MCP 查询却失败？

浏览器与 MCP 进程可能使用不同的出口、登录会话、Cookie 或请求通道。网页访问权限与正式 API 权限也可能不同。先核对运行位置、命令要求和上游错误，不要直接复制浏览器全部会话或把 Cookie 发到聊天中。

## 安装器说成功，但 AI 看不到七个工具

这通常还停留在“生成连接配置”阶段。确认客户端真的追加了本服务、使用安装器输出的 Python 和参数、保留其 env，并完成必要的重连。客户端只有 HTTP MCP 配置栏时，不能把本地脚本路径当成远程 URL。

不要为排查一个服务打印全部客户端配置。只检查本服务的名称、启动路径、参数和必要环境字段。

## `choose_mode` 或 `mode_required`

- `choose_mode`：先选 general、zju 或 login。
- `mode_required`：返回所需的 zju 或 login；只为该命令选择对应条件，不影响公开功能。
- `credential_required`：已选择 login，但该个人凭据来源尚未配置；按指定来源向导处理。
- 旧版的 optional_setup_required 是按 starter 限制扩展的返回，v1.3.0 已移除这个门槛。

## 缺依赖、缺文件或上游失败

| 错误/现象 | 含义及处理 |
|---|---|
| `missing_dependency` | 某个适配器缺少库；按实际依赖安装，必要时使用安装器 `--extras` |
| `missing_public_resource` | 找不到依赖的公开文件；根据帮助和官方来源提供正确文件，不解释成无记录 |
| `upstream_timeout` | 上游或网络超时；缩小范围，稍后重试或先换其他来源 |
| `upstream_or_configuration_error` | 包括源站 HTTP、凭据、参数等问题；结合返回信息判断，不统一当成登录问题 |
| `unexpected_output` | 没取得预期 JSON，可能是登录拦截、页面改版或帮助输出 |
| `response_too_large` | 返回超出工具限制；减少数量、时间范围或分页 |
| 返回空列表 | 可能是有效零结果，也可能是筛选/范围问题；核对请求条件和上游说明 |

不要通过关闭 TLS 证书校验来“修复”网络。若修改代理，区分公开网站可达性与机构身份，不要因为能打开首页就认定权限可用。

## 已注册，为什么还不能查询 API？

注册账号、验证邮箱、申请某个 API 产品、拿到密钥、数据权限和真实查询，是不同阶段。向导会分开记录。某些学校网页订阅不包含 API 产品；示例查询成功也不能推定所有库、全文或年份均可用。

## 钥匙串或系统安全存储不能用

macOS 可能出现访问授权提示。Windows/Linux 或云端容器需要支持的系统安全存储后端。也可以由用户在服务的安全环境设置里显式配置专用变量。不要把密钥写入 README、代码、发行包或聊天消息。

保存凭据时，运行副本的 `onboarding.py` 必须使用与 MCP 相同的 `RESEARCH_MCP_STATE_DIR` 和 login 模式。否则可能出现“配置在另一个状态目录”的误会。

## 暂停后会丢进度吗？

不会主动清空。调用 pause 会保存暂停标记；resume 会接续步骤。切换 general/zju/login 也保留进度。保存的是步骤和测试状态，不是浏览器登录备份；网站会话或令牌过期仍要处理。

## 更新以后为什么还在运行旧版？

安装器会生成新版代码副本与连接路径。需要让客户端使用新生成的连接配置并重新连接；仅解压 ZIP 不会替换已有进程。更新时使用同一个独立安装根目录，可保留已有状态；不要删除 state 目录。

## 为什么严格校验报告额外文件？

严格校验针对干净发行包。`.venv`、缓存、生成配置、进度、`.DS_Store` 或仓库的 `.git` 都不在发行清单中。若原始清单文件仍正确，`pack_release.py` 可只导出白名单文件；如果原始文件被修改，则拒绝打包，应先核对修改，不能盲目重写哈希绕过。

## 能不能把文件夹转给别人后直接带上我的登录状态？

发行设计不携带账号、凭据或会话。接收者使用自己的账号和权限。请转发原始 Release ZIP 或专用打包脚本输出，不转发自己的安装根目录、进度、客户端配置或平台截图。

## 提问题时该提供哪些信息？

提供版本、操作系统、客户端是否支持 stdio、MCP 在本机还是云端、命令名、可公开的参数和脱敏错误。附上是否处于 general/zju/login，以及失败发生在连接、帮助还是实际查询阶段即可。

不要附上密码、令牌、Cookie、授权头、完整客户端配置、学校身份信息或私人研究内容。维护者无法凭这些信息为你授予数据库权限。

## v1.2.0：参数错误有独立分类

例如 `arxiv` 接受 `--size`，不接受 Crossref 使用的 `--rows`。错误参数现在返回 `invalid_arguments`，包含短 `message`、当前命令的 `usage`、`supported_options` 和针对性 `hint`。不会再夹带几千个命令名，也不会误导去检查网络、文件或密钥。

`mode_required` 是访问条件限制，与参数或上游故障不同。所有无需个人凭据/机构网络的公开命令现在均可在 general 尝试，五个统计局数值流程也包含在内。

### 获取脱敏诊断

使用**安装后的运行副本**及其 Python、状态目录运行：

```sh
python3 -B doctor.py
```

复现一条错误调用可加：

```sh
python3 -B doctor.py --command arxiv --args-json '["digital economy","--rows","2"]'
```

报告只显示版本、系统、Python、代理/CA 是否配置等状态，不打印其具体值或研究结果。需要确认客户端确实切到了新版时，核对 MCP 的 `serverInfo.version`；解压新包但没有更新连接路径/重连，仍可能使用旧进程。

网络错误现在尽量区分 HTTP、证书、代理、DNS、超时与响应格式；旧适配器可能仍只能提供通用错误。ONS 首个目录页失败会返回失败，部分页失败则带 `partial` 和 `warnings`，不能将失败页解释成没有匹配数据。

诊断中的代理/CA 标记只说明相应环境变量是否设置，不能判断系统代理、TUN 或最终出口。目录检索还受原站语言和大小写规则影响；零结果应核对原站词汇和筛选范围。

错误返回的结构示例（省略非关键字段）：

```json
{
  "ok": false,
  "command": "arxiv",
  "error": "invalid_arguments",
  "message": "unrecognized arguments: --rows 2",
  "usage": "usage: research.py arxiv [-h] [--size SIZE] [--start START] keyword",
  "supported_options": ["-h", "--help", "--size", "--start"]
}
```

若参数取值校验发生在某个旧适配器内部，仍可能返回 `invalid_arguments_or_response`；这表示需要核对具体检查信息，不应直接判断是断网或缺密钥。

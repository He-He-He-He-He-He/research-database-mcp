## 已定位的接收端问题

接收端在 Debian 12 / Python 3.11.2 使用 `--rows` 调用只接受 `--size` 或 `--limit` 的命令，触发参数错误；原版本将其包装为上游错误并附带巨型命令目录。接收端改用正确参数后，arXiv、PubMed、ONS、USGS 和法律检索均能返回。这一事实不支持“Linux 适配器损坏”的早期判断。

v1.2.0 为这条真实错误路径加入回归检查：`invalid_arguments`、短摘要、当前命令 usage、可用选项及正确数量参数提示；与模式限制、上游失败分开。

## 检查项目

- 18 项原有离线检查：协议、安装入口、状态、隔离、参数类型、语法等。
- 8 项发行检查：白名单、额外文件拒绝、确定性 ZIP、配置/缓存排除等。
- 21 项新增诊断检查：真实错误参数、缺参数、数量参数、模式提示、数值入口开放、发现层级、失败页、脱敏诊断、指定来源恢复及升级保留暂停。其一还逐项检查全部 42 个起步命令的帮助入口。

合计 47 项离线测试，不等于 42 个来源的联网验收。

## 联网样例

`tools/public_check.py --suite all` 对 13 个公开入口及 5 条中国数值查询链做显式抽样，使用临时 partial 配置，不读取实际用户凭据，只输出状态与行数等摘要。目录、元数据、题录和观测数值分别标记。中国查询链核对全国地区及实际候选代码，并检查返回值确实可解析为数字。

来源可能限流、按地区限制或临时超时，工作流会将联网结果保存为独立 artifact；离线工作流通过不能替代阅读联网报告。个别样例成功也不等于某来源的全部数据已验证。

## 跨系统

GitHub Actions 对 Linux、macOS、Windows 执行离线测试，并在 Linux 执行公开样例。当前执行结果与具体范围将在本次发布验收后记录于本页。

不把旧版在接收端的成功自动记为新版全部参数通过，不把任意服务器首页的 HTTP 200 当作 API 查询成功。
